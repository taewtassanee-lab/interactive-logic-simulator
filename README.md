# Interactive Logic Simulator

**ระบบจำลองตรรกะ Array และ Function สำหรับ Construct 2**

สื่อนวัตกรรมการเรียนรู้สำหรับนักเรียนชั้นมัธยมศึกษาปีที่ 5
รายวิชาเพิ่มเติม คอมพิวเตอร์ 4 (ว32281) — หน่วยการเรียนรู้ที่ 2: การสร้างสื่อปฏิสัมพันธ์ด้วย Construct 2

นักเรียนจับคู่แบบ Pair Programming (Driver / Navigator) เพื่อเรียงบล็อกคำสั่ง ทดลอง Run
เห็นการเปลี่ยนแปลงของ Array ตัวแปร คะแนน และเงื่อนไขจบเกมแบบ Real-time แก้ Bug 2 ภารกิจ
ทำใบงานดิจิทัลบนหน้าเว็บ ดาวน์โหลดเป็น PDF แล้วนำไปแนบส่งใน Google Classroom ด้วยตนเอง

## ธีมและกราฟิก 3 มิติ

หน้าเว็บใช้สไตล์ 3 มิติแบบ Claymorphism (วัตถุกลมมนคล้ายดินปั้น) เพื่อให้ผู้เรียนรู้สึกอยากทดลองเล่น

| องค์ประกอบ | ทำอย่างไร |
| --- | --- |
| มาสคอตหุ่นยนต์ / ตัว Bug | SVG วาดเอง ใส่ไล่เฉดสีและเงาซ้อนชั้นให้ดูมีปริมาตร ลอยขึ้นลงเบา ๆ |
| ลูกบาศก์ Array | SVG ไอโซเมตริก 3 หน้า (บน/ซ้าย/ขวา) แทนข้อสอบ 1 ข้อ ช่องที่ถูกลบจะหายไปจริง ช่องที่กำลังสุ่มจะขยายและเปลี่ยนเป็นสีม่วง |
| เหรียญตรา | ทรงกลมไล่เฉดสี มีขอบล่างหนา แสงวิ่งผ่าน และริบบิ้นใต้เหรียญ เหรียญที่ยังไม่ได้รับเป็นสีเทา |
| ปุ่มและบล็อกคำสั่ง | ใช้ `box-shadow` เป็นขอบหนาด้านล่าง กดแล้วยุบลงจริงด้วย `translateY` |
| การ์ดทุกใบ | คลาส `.clay-card` ใน `src/index.css` มุมโค้ง 28px พร้อมขอบล่างหนาและเงาฟุ้ง |
| พื้นหลัง | ไล่เฉดสีอ่อน + ทรงกลม 4 ก้อนลอยอยู่ด้านหลัง (คอมโพเนนต์ `FloatingShapes`) |

**ไม่ได้ใช้ไลบรารี 3D อย่าง three.js โดยตั้งใจ** เพราะเว็บนี้ต้องเปิดได้ลื่นบนคอมพิวเตอร์โรงเรียนและมือถือนักเรียน
SVG + CSS ให้ผลลัพธ์ที่ต้องการโดยไม่เพิ่มขนาดไฟล์และไม่กินการ์ดจอ ระบบยังหลีกเลี่ยง `backdrop-filter`
กับ `background-attachment: fixed` ซึ่งทำให้เครื่องสเปกต่ำกระตุกเวลาเลื่อนหน้า

**การเข้าถึง:** ภาพเคลื่อนไหวทั้งหมดจะหยุดเองเมื่อผู้ใช้ตั้งค่า "ลดการเคลื่อนไหว" (`prefers-reduced-motion`)
ในระบบปฏิบัติการ และทุกสถานะยังสื่อความหมายด้วยข้อความหรือไอคอนควบคู่กับสีเสมอ

**ใบงาน PDF ยังคงรูปแบบทางการ** ไม่ใช้ธีมน่ารัก เพราะเป็นเอกสารที่ต้องพิมพ์และส่งครูตรวจ
หากต้องการปรับรูปแบบเอกสาร แก้ที่ `src/components/PrintableWorksheet.tsx`

**ถ้าต้องการลดความหวานของธีม**

| อยากแก้ | แก้ที่ไหน |
| --- | --- |
| เปลี่ยนฟอนต์หัวเรื่องกลับเป็นแบบทางการ | `tailwind.config.js` → `fontFamily.display` เปลี่ยนเป็น `IBM Plex Sans Thai` |
| ลดสีชมพู/ม่วง | `tailwind.config.js` → แก้ชุดสี `bubble` และ `think` |
| ปิดภาพเคลื่อนไหวทั้งหมด | ลบ `<FloatingShapes />` ใน `src/App.tsx` และลบคลาส `animate-*` |
| ลดความโค้งของมุมการ์ด | `src/index.css` → `.clay-card` เปลี่ยน `rounded-[1.75rem]` |

## วิธีใส่รูปครูผู้สอน

ระบบแสดงชื่อ **ครูทัศนีย์ ศรีทน** และ **โรงเรียนหนองหงส์พิทยาคม** ไว้แล้วใน 5 จุด
ได้แก่ แถบหัวเว็บ หน้าเริ่มต้นใช้งาน หน้าคู่มือครู ท้ายเว็บ และหัวใบงาน PDF (พร้อมชื่อใต้เส้นลงชื่อครูผู้สอน)

**รูปภาพต้องเพิ่มเอง** โดยบันทึกไฟล์ลงโฟลเดอร์ `public/` ดังนี้

| ไฟล์ | ใช้ทำอะไร | ขนาดที่แนะนำ | จำเป็นไหม |
| --- | --- | --- | --- |
| `public/teacher.jpg` | รูปวงกลมของครู แสดงที่หัวเว็บและการ์ดครูผู้สอน | จัตุรัส เช่น 600x600 px | ไม่บังคับ |
| `public/teacher-banner.jpg` | ภาพแนวนอนขนาดใหญ่ในหน้าคู่มือครู | สัดส่วน 16:7 เช่น 1600x700 px | ไม่บังคับ |

> ไฟล์ทั้งสองใส่ไว้ให้แล้วในโปรเจกต์นี้ หากต้องการเปลี่ยนรูป ให้บันทึกทับไฟล์เดิมโดยใช้ชื่อเดิม

หลังวางไฟล์แล้วรีเฟรชหน้าเว็บได้เลย ถ้าเผยแพร่ไปแล้วให้รัน `npm run build` ใหม่

**ถ้ายังไม่ใส่รูป ระบบก็ทำงานปกติ** — รูปวงกลมจะแสดงอักษรย่อ "ทศ" บนพื้นไล่เฉดสีแทน
ส่วนแบนเนอร์จะไม่แสดงเลย ไม่มีรูปแตกหรือช่องว่างค้างในหน้า

**ถ้าใบหน้าถูกครอปไม่สวยในกรอบวงกลม** ให้แก้ 2 ค่านี้ใน `src/config.ts`

```ts
photoZoom: 2.45,               // ระดับการซูมเข้าหาใบหน้า
photoPosition: 'center 20%',   // จุดกึ่งกลางที่ซูมเข้าไป
```

ค่าที่ตั้งไว้ปรับมาสำหรับรูปเต็มตัวที่ใช้อยู่ (ใบหน้าอยู่ค่อนไปทางบนของภาพ)
ถ้าเปลี่ยนไปใช้รูปหน้าตรงที่ครอปมาแล้ว ให้ตั้ง `photoZoom: 1` และ `photoPosition: 'center'`

| อาการ | แก้อย่างไร |
| --- | --- |
| ใบหน้าเล็กเกินไป | เพิ่ม `photoZoom` เช่น 2.8 |
| ภาพซูมจนหัวโดนตัด | ลด `photoZoom` เช่น 1.8 |
| กรอบอยู่ต่ำกว่าใบหน้า | ลดตัวเลขใน `photoPosition` เช่น `'center 12%'` |
| กรอบอยู่สูงกว่าใบหน้า | เพิ่มตัวเลข เช่น `'center 32%'` |

**แก้ชื่อครู ตำแหน่ง หรือโรงเรียน** ได้ที่ `TEACHER_INFO` ในไฟล์ `src/config.ts`

```ts
export const TEACHER_INFO = {
  name: 'ครูทัศนีย์ ศรีทน',
  formalName: 'นางสาวทัศนีย์ ศรีทน',   // ชื่อที่ใช้ใต้เส้นลงชื่อในใบงาน PDF
  position: 'ครูผู้สอนรายวิชาคอมพิวเตอร์ 4 (ว32281)',
  school: 'โรงเรียนหนองหงส์พิทยาคม',
  initials: 'ทศ',
  ...
};
```

## ความต้องการระบบ

**สำหรับผู้พัฒนา/ผู้ติดตั้ง**

- Node.js เวอร์ชัน 18 ขึ้นไป (แนะนำ 20 หรือ 22 LTS) — ตรวจสอบด้วย `node -v`
- npm เวอร์ชัน 9 ขึ้นไป — ตรวจสอบด้วย `npm -v`
- พื้นที่ว่างประมาณ 300 MB สำหรับ `node_modules`
- การเชื่อมต่ออินเทอร์เน็ตสำหรับติดตั้งครั้งแรก

**สำหรับผู้ใช้งาน (ครูและนักเรียน)**

- เบราว์เซอร์รุ่นใหม่: Chrome, Edge, Firefox หรือ Safari (ใช้ได้ทั้งคอมพิวเตอร์ แท็บเล็ต และมือถือ)
- รองรับหน้าจอตั้งแต่ 360px ถึง 1920px ขึ้นไป (ทดสอบที่ 375px, 768px, 1366px)
- ต้องเปิด JavaScript และไม่ปิดกั้น localStorage
- ไม่ต้องล็อกอิน และไม่ต้องต่ออินเทอร์เน็ตหลังโหลดหน้าเว็บเสร็จ

## วิธีติดตั้งและใช้งาน

### 1) ติดตั้ง dependencies

```bash
npm install
```

### 2) รันเพื่อพัฒนา/ทดลองใช้

```bash
npm run dev
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:5173`

### 3) สร้างไฟล์สำหรับเผยแพร่

```bash
npm run build
```

ผลลัพธ์อยู่ในโฟลเดอร์ `dist/` (ทดสอบสร้างจริงแล้ว ผ่านโดยไม่มี error)

### 4) ทดลองเปิดไฟล์ที่ build แล้ว

```bash
npm run preview
```

### 5) ตรวจสอบคุณภาพโค้ด

```bash
npm run lint
```

## แดชบอร์ดสรุปผลของครู

เว็บมีแท็บ **แดชบอร์ดครู** สำหรับดูความก้าวหน้าของนักเรียนทุกคู่ในที่เดียว

**ค่าเริ่มต้นคือปิดอยู่** ระบบจะเก็บข้อมูลไว้ในเบราว์เซอร์ของนักเรียนเท่านั้นและไม่ส่งข้อมูลออกไปไหน
หากต้องการใช้แดชบอร์ด ต้องเชื่อมต่อกับ Google Sheets ก่อน (ฟรี ใช้บัญชี Google ที่มีอยู่ ใช้เวลาประมาณ 10 นาที)

**ขั้นตอนแบบละเอียดอยู่ที่ [docs/คู่มือติดตั้งแดชบอร์ด.md](docs/คู่มือติดตั้งแดชบอร์ด.md)** สรุปสั้น ๆ คือ

1. สร้าง Google Sheet ใหม่ แล้วเปิดเมนู ส่วนขยาย > Apps Script
2. วางโค้ดจาก [`apps-script/Code.gs`](apps-script/Code.gs) แล้วตั้งรหัส `CLASS_SECRET` กับ `TEACHER_KEY`
3. Deploy เป็น Web app (Execute as: Me, Who has access: Anyone) แล้วคัดลอก URL
4. ใส่ URL และ `classSecret` ลงใน `SYNC_CONFIG` ที่ `src/config.ts` แล้ว `git push`

**แดชบอร์ดแสดงอะไรบ้าง**

- จำนวนคู่ที่เริ่มกิจกรรม, เปอร์เซ็นต์ที่ผ่านภารกิจที่ 1 และ 2, เปอร์เซ็นต์ที่ได้เหรียญ Logic Master
- ใบงานเฉลี่ยทั้งห้อง, จำนวนที่สร้าง PDF แล้ว, จำนวนที่แนบไฟล์ .capx แล้ว
- ตารางรายคู่พร้อมชื่อ Driver/Navigator สถานะภารกิจ คะแนน และเวลาอัปเดตล่าสุด
- รีเฟรชอัตโนมัติทุก 30 วินาที, ค้นหาตามห้อง/รหัสคู่/ชื่อนักเรียน, ดาวน์โหลด CSV เปิดด้วย Excel ได้

**ข้อมูลที่ส่งขึ้นเซิร์ฟเวอร์เป็นเพียงสรุปความก้าวหน้าเท่านั้น**
ไม่รวมคำตอบเรียงความในใบงาน เพราะคำตอบฉบับเต็มอยู่ในไฟล์ PDF ที่นักเรียนส่งใน Classroom อยู่แล้ว

> **ข้อจำกัดด้านความปลอดภัย** เว็บนี้เป็น repository สาธารณะ ค่า `classSecret` จึงเปิดดูได้

## การส่งงานใน Google Classroom

**ระบบไม่ได้เชื่อมต่อกับ Google Classroom** และไม่มีช่องกรอกลิงก์ในเว็บ
นักเรียนจะเปิด Google Classroom ของชั้นเรียนด้วยตนเองแล้วแนบไฟล์ที่ดาวน์โหลดจากเว็บ

**สิ่งที่ครูต้องเตรียม**

1. สร้างงานใน Classroom ล่วงหน้า ตั้งชื่อให้ตรงกับกิจกรรม
2. ตั้งค่าให้นักเรียนแนบไฟล์ได้ 2 ไฟล์ คือใบงาน PDF และไฟล์ผลงาน `.capx`

**สิ่งที่นักเรียนทำในเว็บ**

1. กดปุ่ม "สร้างและดาวน์โหลดใบงาน PDF" ในหน้าสรุปและส่งงาน

3. เปิด Google Classroom เอง แล้วแนบไฟล์ PDF พร้อมไฟล์ `.capx`

## วิธีเผยแพร่ระบบ

โปรเจกต์ตั้งค่า `base: './'` ไว้แล้ว จึงวางที่ path ใดก็ทำงานได้

### ตัวเลือกที่ใช้อยู่ตอนนี้ — GitHub Pages (ตั้งค่าเสร็จแล้ว)

ระบบเผยแพร่อยู่ที่ https://taewtassanee-lab.github.io/interactive-logic-simulator/ แล้ว
ไฟล์ตั้งค่าอยู่ที่ `.github/workflows/deploy.yml`

**วิธีอัปเดตเว็บหลังแก้ไขโค้ด**

```bash
git add -A
git commit -m "อธิบายสิ่งที่แก้"
git push
```

GitHub จะ build และอัปเดตเว็บให้เองภายใน 1-2 นาที ไม่ต้องรัน `npm run build` เอง

### ตัวเลือก A — Netlify (ง่ายที่สุด ไม่ต้องใช้ Git)

1. รัน `npm run build`
2. เปิด <https://app.netlify.com/drop>
3. ลากโฟลเดอร์ `dist` ทั้งโฟลเดอร์ไปวาง
4. รับลิงก์แล้วนำไปแจกนักเรียนได้ทันที

หรือเชื่อมกับ GitHub repo แล้วตั้งค่า
Build command: `npm run build` | Publish directory: `dist`

### ตัวเลือก B — GitHub Pages

1. สร้าง repository บน GitHub แล้ว push โค้ดขึ้นไป
2. ติดตั้งเครื่องมือช่วย deploy

```bash
npm install --save-dev gh-pages
```

3. เพิ่มสคริปต์ใน `package.json`

```json
"scripts": {
  "deploy": "npm run build && gh-pages -d dist"
}
```

4. รัน

```bash
npm run deploy
```

5. ไปที่ Settings → Pages ของ repository แล้วเลือก branch `gh-pages`

### ตัวเลือก C — เปิดจากเครื่องแม่ข่ายของโรงเรียน

คัดลอกทุกไฟล์ในโฟลเดอร์ `dist` ไปวางใน web root (เช่น `htdocs` หรือ `www`) ได้เลย
ระบบเป็น Static Site ไม่ต้องใช้ PHP ฐานข้อมูล หรือ Node บนเซิร์ฟเวอร์

## ฟอนต์ไทยใน PDF

ระบบสร้าง PDF ด้วยวิธี **HTML → Canvas → PDF** (html2canvas + jsPDF) ไม่ใช่การเขียนข้อความลง jsPDF โดยตรง

**เหตุผล:** jsPDF ใช้ฟอนต์มาตรฐาน (Helvetica) ที่ไม่มีสระและวรรณยุกต์ไทย
ถ้าเรียก `pdf.text('ภาษาไทย', x, y)` ตรง ๆ ตัวอักษรจะกลายเป็นสี่เหลี่ยมหรือหาย
การ render ผ่านเบราว์เซอร์ก่อนแล้วจับภาพ ทำให้ได้ผลลัพธ์ตรงกับที่นักเรียนเห็นบนหน้าจอทุกตัวอักษร
รวมถึงสระบน-ล่างและวรรณยุกต์ที่ซ้อนกัน

**ผลที่ได้:** ไฟล์ PDF ขนาด A4 แบ่งหน้าอัตโนมัติ (ปกติ 3 หน้า) ข้อความไทยคมชัด พิมพ์อ่านง่าย
ข้อแลกเปลี่ยนคือข้อความในไฟล์เป็นภาพ จึงค้นหาข้อความ (Ctrl+F) ในไฟล์ PDF ไม่ได้
ซึ่งไม่กระทบการใช้งานจริง เพราะครูตรวจจากการอ่านและพิมพ์เอกสาร

**หากต้องการ PDF ที่ค้นหาข้อความได้** (ไม่จำเป็นสำหรับกิจกรรมนี้) ให้ฝังฟอนต์ไทยลง jsPDF ดังนี้

1. ดาวน์โหลดฟอนต์ไทยแบบ TTF ที่อนุญาตให้ฝังได้ เช่น Sarabun หรือ Noto Sans Thai จาก Google Fonts
2. แปลงเป็น base64 ด้วยเครื่องมือ [jsPDF Font Converter](https://rawgit.com/MrRio/jsPDF/master/fontconverter/fontconverter.html)
   จะได้ไฟล์ `.js` มาหนึ่งไฟล์
3. วางไฟล์นั้นไว้ที่ `src/utils/fonts/Sarabun-normal.js` แล้ว import ในไฟล์ที่สร้าง PDF
4. เรียกใช้งาน

```ts
import { jsPDF } from 'jspdf';
import './fonts/Sarabun-normal';

const pdf = new jsPDF();
pdf.setFont('Sarabun', 'normal');
pdf.text('ทดสอบภาษาไทย', 20, 20);
```

> ข้อควรระวัง: ฟอนต์ไทยบางตัวยังจัดตำแหน่งสระซ้อนไม่ถูกต้องใน jsPDF และไฟล์ base64
> จะเพิ่มขนาด bundle ประมาณ 300–500 KB จึงเลือกใช้วิธี HTML → Canvas เป็นค่าเริ่มต้น

## ขั้นตอนใช้งานสำหรับครู

1. **ก่อนคาบเรียน** — เปิดระบบทดลองใช้เอง โดยกรอกข้อมูลสมมติแล้วทำกิจกรรมจนจบ
   เพื่อดูหน้าตาใบงานและไฟล์ PDF ที่นักเรียนจะส่ง (อย่าลืมกด Reset ข้อมูล เมื่อทดลองเสร็จ)
2. **สร้างงานใน Classroom** ล่วงหน้า และตั้งค่าให้แนบไฟล์ได้ทั้ง PDF และ .capx
3. **แจกลิงก์เว็บแอป** ให้นักเรียนพร้อมกำหนดรหัสคู่ เช่น Pair01–Pair20
4. **สอนตามแผน GPAS 5 Steps** ในหน้า "คู่มือครู" (Gathering 10 / Processing 10 / Applying 25 / Communicating 10 / Self-Regulating 5 นาที)
5. **เตือนให้สลับบทบาท** ทุก 10 นาทีตาม Role Switch Timer
6. **ตรวจงาน** — เปิดไฟล์ PDF ดูส่วนที่ 1–3, ตาราง Debugging Log และผลการผ่านภารกิจ
   แล้วเทียบกับ Event Sheet ในไฟล์ .capx ว่ามีคำสั่ง `Delete index` และเงื่อนไข `Array is empty` จริง

## ขั้นตอนใช้งานสำหรับนักเรียน

1. เปิดลิงก์เว็บแอปที่ครูให้มา กรอกห้องเรียน รหัสคู่ ชื่อ Driver และ Navigator แล้วกด **"เริ่มกิจกรรม"**
2. เปิดแท็บ **"คลังความรู้"** อ่านทำความเข้าใจ Array และ Function ก่อนลงมือ
   มีส่วนให้ลองกดลบช่อง Array เพื่อดูว่า Index และ Array.Width เปลี่ยนอย่างไร
   (เปิดกลับมาดูได้ตลอดเวลาระหว่างทำกิจกรรม)
3. ไปที่แท็บ **"จำลองตรรกะ"** กดปุ่ม **"โหลดตัวอย่างตรรกะที่มี Bug"** แล้วกด **Run Simulation**
   สังเกตอาการปัญหาใน State Monitor และ Debug Log
4. แก้ตรรกะโดยเพิ่ม ลบ หรือเลื่อนบล็อก จนผ่านทั้ง 2 ภารกิจและได้เหรียญ **Logic Master**
   (กด "แสดงคำใบ้" ได้เมื่อติดขัด และ "Run ทีละขั้น" เพื่อดูทีละคำสั่ง)
5. นำตรรกะที่ถูกต้องไปแก้ Event Sheet จริงใน Construct 2 แล้วบันทึกไฟล์ `.capx`
6. ไปที่แท็บ **"ใบงานดิจิทัล"** กรอกให้ครบทั้ง 3 ส่วนจนแถบความครบถ้วนขึ้น **100%**
   (ใช้ปุ่ม "ดึง Debug Log ล่าสุด" เพื่อแนบหลักฐาน)
7. ไปที่แท็บ **"สรุปและส่งงาน"** กด **"ตรวจสอบความพร้อมก่อนส่ง"** แล้วแก้รายการที่ยังไม่ครบ
8. กด **"สร้างและดาวน์โหลดใบงาน PDF"** จะได้ไฟล์ชื่อ `Worksheet_QuizDebug_M5-1_Pair01.pdf`
9. กด **"คัดลอกข้อความสำหรับส่งงาน"** แล้ว **เปิด Google Classroom ของชั้นเรียนเอง**
   แนบไฟล์ PDF พร้อมไฟล์ .capx ในงานที่ครูมอบหมาย จากนั้นกดส่ง

## ข้อจำกัดของระบบเวอร์ชันนี้

- **ไม่ได้เชื่อมต่อ Google Classroom API** — ระบบไม่มีลิงก์หรือปุ่มเปิด Classroom
  **นักเรียนต้องเปิด Classroom เองแล้วแนบไฟล์ PDF และไฟล์ .capx ด้วยตนเอง** ระบบไม่ได้ส่งงานให้อัตโนมัติ
- **ไม่มีระบบล็อกอิน** — ข้อมูลหลักเก็บใน `localStorage` ของเบราว์เซอร์เครื่องที่ใช้
  หากเปิดใช้แดชบอร์ด จะมีสำเนาสรุปความก้าวหน้า (ไม่รวมคำตอบใบงาน) อยู่ใน Google Sheets ของครูด้วย
  ถ้าเปลี่ยนเครื่อง เปลี่ยนเบราว์เซอร์ ใช้โหมดไม่ระบุตัวตน หรือล้างข้อมูลเบราว์เซอร์ ข้อมูลจะหาย
  ครูจึงควรย้ำให้นักเรียนดาวน์โหลด PDF ก่อนปิดเครื่องทุกครั้ง
- **การอัปโหลด `.capx` เก็บเฉพาะข้อมูลไฟล์** (ชื่อ ขนาด เวลาที่แนบ) ไม่ได้อัปโหลดตัวไฟล์ขึ้นเซิร์ฟเวอร์
  ใช้เพื่อยืนยันว่านักเรียนเตรียมไฟล์แล้วเท่านั้น
- **ครูดูความคืบหน้าแบบรวมศูนย์ไม่ได้ ถ้ายังไม่ได้เชื่อม Google Sheets** (ดูวิธีเปิดใช้ที่หัวข้อแดชบอร์ดสรุปผลของครู)
- **ข้อความใน PDF เป็นภาพ** จึงค้นหาข้อความในไฟล์ไม่ได้ (ดูเหตุผลในหัวข้อ [ฟอนต์ไทยใน PDF](#ฟอนต์ไทยใน-pdf))
- **ตัวจำลองไม่ใช่ Construct 2 จริง** เป็นแบบจำลองเชิงตรรกะที่ออกแบบให้เห็นหลักการ
  นักเรียนยังต้องนำตรรกะไปสร้างใน Construct 2 เอง
- ตัวจำลองหยุดการทำงานที่ 10 รอบ เพื่อกันการวนซ้ำไม่รู้จบเมื่อตรรกะยังไม่ถูกต้อง

## การแก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
| --- | --- |
| กดแท็บ "จำลองตรรกะ" แล้วเด้งกลับหน้าแรก | ยังไม่ได้กด "เริ่มกิจกรรม" หรือกรอกชื่อ Driver / Navigator / รหัสคู่ ไม่ครบ |
| ข้อมูลที่กรอกไว้หายไป | เปลี่ยนเบราว์เซอร์หรือเครื่อง / ใช้โหมดไม่ระบุตัวตน / มีการล้างข้อมูลเบราว์เซอร์ |
| กด Run แล้วขึ้น Bug Detected ตลอด | ยังมีบล็อกหมวด Bug ค้างอยู่ใน Workspace หรือเรียงลำดับผิด — กด "แสดงคำใบ้" |
| กดสร้าง PDF แล้วไม่มีอะไรเกิดขึ้น | ใบงานยังไม่ครบ ระบบจะแจ้งรายการที่ขาดก่อน / เบราว์เซอร์บล็อกการดาวน์โหลด ให้อนุญาตแล้วลองใหม่ |
| PDF ออกมาเป็นหน้าว่าง | ฟอนต์ยังโหลดไม่เสร็จ รอสัก 2–3 วินาทีหลังเปิดหน้าเว็บแล้วกดใหม่ |
| ปุ่มคัดลอกไม่ทำงาน | เบราว์เซอร์ไม่อนุญาต Clipboard API ให้เลือกข้อความในกรอบแล้วกด Ctrl+C แทน |
| `npm install` ล้มเหลว | ตรวจสอบ Node.js เวอร์ชัน 18 ขึ้นไป แล้วลบ `node_modules` กับ `package-lock.json` ก่อนติดตั้งใหม่ |
